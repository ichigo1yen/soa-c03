質問#011

ある企業は、300 を超える Linux ベースのインスタンスでビジネス アプリケーションを運用しています。各インスタンスには AWS Systems Manager Agent (SSM Agent) がインストールされています。同社は、今後インスタンス数が増加すると予想しています。すべてのビジネス アプリケーション インスタンスには、同じユーザー定義タグが付けられています。CloudOps
エンジニアは、すべてのビジネス アプリケーション インスタンスでコマンドを実行し、プライベート リポジトリからパッケージをダウンロードしてインストールしたいと考えています。リポジトリへの負荷を軽減するため、CloudOps エンジニアは、一度に 30 を超えるダウンロードが発生しないようにしたいと考えています。
どのソリューションが、この要件を最も運用効率の良い方法で満たすでしょうか。

  • A. セカンダリタグを使用して、30インスタンスずつ10バッチを作成します。Systems Manager実行コマンド文書を使用してパッケージをダウンロードしてインストールします。実行コマンド文書の一部として、セカンダリタグを使用してターゲットを指定します
    。各バッチを1回実行します。
  • B. AWS Lambda 関数を使用して、ユーザー定義タグを持つインスタンス ID のリストを含む Systems Manager 実行コマンド ドキュメントを自動的に実行します。Lambda 関数の予約済み同時実行数を 30 に設定します。
  • C. Systems Managerの実行コマンド文書を使用してパッケージをダウンロードしてインストールします。レート制御を使用して同時実行数を30に設定します。実行コマンド文書の一部としてユーザー定義タグを使用してターゲットを指定します。
  • D. AWS Step Functions の並列ワークフロー状態を使用して、ユーザー定義タグを持つインスタンス ID のリストを読み取る Systems Manager 実行コマンド ドキュメントを自動的に実行します。並列状態の数を 30 に設定します。Step Functions ワークフローを 10 回実行します。
